# SillyTavern-DraftGuard

**输入框保护 · 草稿时光机**

SillyTavern（酒馆）前端扩展。输入时每 3 秒保存一次有变化的内容；点击魔棒菜单里的 **草稿保护** 查看、恢复或导出历史。无需后端插件、API 密钥或构建步骤。

## v1.0.1

- 入口移到魔棒菜单，显示为“草稿保护”，不再向输入框侧栏添加按钮。
- 优先使用酒馆自带弹窗，改善主题兼容性。
- 点击时重新同步聊天状态；未打开聊天时给出明确提示。
- 保留原有浏览器草稿数据库，更新后无需迁移历史。

## 安装

### 推荐：通过酒馆安装

打开酒馆的 **扩展 → 安装扩展**，粘贴仓库地址：

```text
https://github.com/notyourlittlecheese/SillyTavern-DraftGuard
```

安装完成后刷新网页，在扩展管理中确认已启用。进入聊天，点击魔棒菜单里的 **草稿保护** 查看历史。以后可通过酒馆扩展管理检查更新。

### 手动安装

1. 解压 ZIP，取得 `tavern-draft-guard` 文件夹。
2. 将整个文件夹放进你的酒馆安装目录下：
   `data/<你的用户账号>/extensions/tavern-draft-guard/`
   普通单用户安装通常是 `data/default-user/extensions/tavern-draft-guard/`。
   也可以放在 `public/scripts/extensions/third-party/tavern-draft-guard/`，供所有酒馆账号加载。
3. 确认 `manifest.json` 就在该文件夹第一层，不要多套一层文件夹。
4. 刷新酒馆网页，在扩展管理中确认“输入框保护 · 草稿时光机”已启用。打开聊天后，魔棒菜单中出现 **草稿保护**。

手机浏览器连接电脑/服务器上的酒馆时，文件应放到运行酒馆的电脑/服务器。手机本地运行酒馆则放进手机上的酒馆安装目录。GitHub 下载的 ZIP 也可手动安装：将解压后的仓库文件夹改名为 `tavern-draft-guard`，再按上述步骤放置。

## 历史清理规则

每个聊天独立保留两部分：**正在写的草稿**、**最近一条已发送消息的历史**。

| 操作 | 保留内容 |
| --- | --- |
| 正在写第 1 楼 | 第 1 楼草稿历史 |
| 第 1 楼发送 | 第 1 楼历史仍保留 |
| 正在写第 3 楼 | 第 1 楼历史 + 第 3 楼草稿历史 |
| 第 3 楼发送 | 删除第 1 楼快照，保留第 3 楼历史 |
| 正在写第 5 楼 | 第 3 楼历史 + 第 5 楼草稿历史 |
| 第 5 楼发送 | 删除第 3 楼快照，保留第 5 楼历史 |

“发送”以酒馆 `MESSAGE_SENT` 事件为准：用户消息已写入聊天。AI 随后回复失败，不会撤销这次轮换；仅点击发送但没有生成该事件，不会清理上一楼。AI 回复、重新生成和滑动回复不会轮换历史。脚本/快捷回复如果发送了用户消息，也会更新最近已发送历史；仍留在输入框中的独立草稿会继续保留。

发送前不足 3 秒的修改，会在酒馆清空输入框时补存。恢复历史前也会保存现有输入，防止误恢复覆盖；若这一步保存失败，则拒绝覆盖原文。恢复后如需撤回，再打开历史选择刚才的内容即可。刷新后不会自动覆盖输入框，请手动选择版本恢复。

## 保存位置与性能

- 数据存入本浏览器、当前酒馆网址下独立的 **IndexedDB 数据库 `tavern-draft-guard-v1`**，包含 `chats` 和 `snapshots` 两张表。
- 不写 `settings.json`、`extension_settings`、`accountStorage`、聊天文件或聊天 metadata。没有服务器保存请求，也没有遥测。
- 账号、角色/群组、聊天分别隔离。网址（协议、域名、端口）变化后，浏览器会视为另一份存储。
- 只在正文变化后安排一次 3 秒保存任务；持续输入会继续保存，空闲没有轮询。每次只写新快照及少量索引，不重写整份历史。
- 中文输入法组合期间暂停定时保存，确认选字后继续。失焦、切聊天、切后台会尝试补存，后台不运行保存定时器。
- 查看历史时只加载版本索引和选中的一份正文，避免一次渲染全部长文本。
- 每楼最多 **120 个版本、1 MiB 正文**，先到哪个限制就先裁掉最旧版本。单快照最多 **262144 个 UTF-16 字符**，超限会明确报错，不静默截断。
- 最多保留 **32 个聊天**，超出时淘汰最久未更新的聊天历史。正文总量理论上限约 **64 MiB**，数据库索引另有少量开销。这些上限用于避免长时间使用后无限增长。

历史是浏览器数据库记录，并非服务器上的独立 JSON 文件。可用“导出所选 TXT”保存成普通文本文件。清除站点数据、无痕会话结束、浏览器回收存储会丢失本地历史；换设备不自动同步。关闭网页时的补存是尽力而为，浏览器被强制杀死可能丢失最后一个保存周期内的输入。

## 验证与兼容范围

按 [SillyTavern 扩展文档](https://docs.sillytavern.app/for-contributors/writing-extensions/) 和 [SillyTavern 源码提交 06bde939](https://github.com/SillyTavern/SillyTavern/tree/06bde939fb1e9c4c8d8641d810f0a916b5bce127)（源码版本 1.19.0）核对扩展清单、输入框和发送事件。需要支持 IndexedDB、ES modules、酒馆弹窗（旧版回退到原生 dialog） 的现代浏览器。已兼容局域网 HTTP 下不可用的 `crypto.randomUUID`。

交付前在真实 Chromium 浏览器、模拟酒馆 DOM/事件的测试页通过 **17 项检查**，覆盖发送轮换、实际删除、末尾补存、刷新恢复、隔离、输入法、发送延迟、存储故障、字数/版本/聊天上限、后台和空闲行为。详见 `TEST-REPORT.json`，测试源在 `tests/smoke.cjs`。

测试不是完整酒馆服务器联调，也不是手机真机温度测试；插件做了低负载和有界存储设计，但无法对任意手机、浏览器或其他扩展组合承诺绝不发热/卡顿。自定义主题隐藏输入框侧边栏、替换原输入框 DOM 或重写发送流程的扩展，可能需要适配。多个页面同时编辑同一聊天时，版本会共用同一份数据库，不提供编辑锁。

开发者复测（普通使用无需执行）：

```sh
npm install --no-save playwright@1.62.1
npx playwright install chromium
node tests/smoke.cjs
```

也可设置 `TDG_BROWSER` 指向已有 Chromium/Edge 可执行文件，设置 `TDG_PLAYWRIGHT` 指向已有 Playwright 模块路径。测试只操作临时浏览器环境，结果输出到 `work/`。

## 卸载

禁用扩展并刷新即可停止运行。若删除扩展文件，本地历史仍在；要一并删除历史，可在浏览器开发者工具的 IndexedDB 面板删除 `tavern-draft-guard-v1`。不要为此清除酒馆整个站点的数据。
